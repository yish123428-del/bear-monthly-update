# Google Sheet 「Bear 아이디어 제안」 구조와 변환 규칙

`scripts/sheet_to_proposals.py` 가 읽는 원본 시트의 구조. Drive 파일 ID 는 `config.json` 의 `sheet.file_id`.

## 읽는 방법

`mcp__Google_Drive__download_file_content(fileId, exportMimeType="text/csv")` 를 쓴다.

- CSV 는 **첫 탭('현황판') 전체**(모든 행)를 담는다. 하네스가 `{"content": "<base64>", "mimeType": "text/csv"}`
  JSON 파일로 저장하고 경로를 알려준다 → 그 경로를 `--dump` 로 넘기면 `dumpio.load_dump` 가 base64 를 푼다.
- `read_file_content` 는 2026-10 부터 "corpus_document" 형식으로 탭별 **샘플 행 몇 개만** 돌려주므로 전체 데이터를 못 얻는다.
  (그 이전의 markdown 표 전체 덤프 형식은 `parse_dump` 가 계속 받는다. 그 경우 탭 이름 없이 모든 탭이 이어붙어 있어
  앵커가 두 번 잡히면 첫 블록을 쓴다.)
- 샌드박스에서 `docs.google.com/.../export` 는 프록시(403)에 막힌다.

## 탭 순서 (2026-09 기준)

1. **현황판** — 원본 표. 이것만 쓴다.
2. 구버전 복제 탭 — 같은 헤더(현황 컬럼 라벨만 `현황`). 앵커가 두 번 잡히면 **첫 블록**을 쓴다.
3. 제품 검토 프로세스, 4. 건의사항, 5. 드롭다운 목록 — 무시.

## '현황판' 헤더 (22열)

```
제안월 | 본부 | 사업부 | 사업팀(MKT)  사무소(영업) | 접수자 | 소속 | 제안자 | 진료과 | 품목 분류 | 개발 형태 |
대분류 | 소분류 | 주요 적응증 | 대표 제품명 | 성분 / 함량 | 제형 | 제품 제안 사유 | 검토 부서 | 담당자 | (빈 헤더=현황) | 세부 현황 | 검토 내용
```

- 앵커: `config.sheet.anchor_labels` (`제안월, 접수자, 대분류, 대표 제품명, 세부 현황`)가 모두 있는 행.
- 컬럼은 라벨 **부분일치**로 찾는다(`COLUMN_MAP`). `현황`(진행중/검토 중단)은 헤더가 비어 있어
  `세부 현황` 바로 앞 칸으로 잡는다.
- 데이터 블록은 `|` 없는 줄에서 끝난다. 제안월 패턴(`\d{2}[년냔]\s*\d{1,2}월`)에 안 맞는 행은 건너뛰고 경고.

## 시트 → 스킬 입력 매핑

| 스킬 입력 (`references/input_format.md`) | 시트 원천 | 규칙 |
|---|---|---|
| 제안 연월 | 제안월 | `"24년  11월"`, `"24냔 11월"` → `"24년 11월"` |
| 본부 | 본부 | `config.mapping.bonbu` 정규식 → `MKT` / `영업본부` |
| 사업부 | 사업부 | MKT 면 `사업부` 접미 (`마케팅1` → `마케팅1사업부`) |
| 팀/사무소 | 사업팀(MKT) 사무소(영업) | `team_aliases` 우선(`호피안` → `호흡피부안과사업팀`), 없으면 MKT 는 `사업팀` 접미, 영업은 사무소명 그대로 |
| 제안자 | **접수자** | 시트의 `제안자` 열은 KOL(외부 제안자)이므로 쓰지 않는다 |
| 건수 | — | 행당 1 (같은 사람 여러 건이면 행이 여러 개) |
| 제안 유형 | 품목 분류 + 개발 형태 | `"의약품 자체개발"` (개발 형태의 공백 제거) |
| 아이디어 유형 | 대분류 | 그대로 |
| 제안 내용 | 대표 제품명 / 성분 / 소분류 / 주요 적응증 | 스크립트가 초안(`_draft: true`)을 만들고 Claude 가 문구만 다듬는다. 60자 넘는 성분표는 잘라낸다(원문은 `_source`) |
| 검토 결과 | 세부 현황 + 현황 | `config.mapping.review_status.rules` → 없으면 현황=`검토 중단` 이면 `검토 중단`, 아니면 세부 현황 그대로 |
| 이메일 표기 | — | 비움 (메일 스크립트가 `{아이디어 유형} {건수}건 ({제안 내용})` 으로 생성) |

## 신규 행 선택

- 보고월의 **전월** 제안월과 같은 행 = 신규.
- `selection.catchup_since`(26년 1월) 이후 행 중 베이스 현황판 시트2
  `(제안 연월, 제안자, 아이디어 유형)` 키에 없는 것 = 캐치업(경고와 함께 포함).
- 전월 행이 이미 베이스 시트2에 있으면 건너뛴다(재실행 대비).
- 중복 제거 키: `(월, 접수자, 대분류, 제품명|성분 공백제거)`.

## 누계

베이스 시트1 `[ 누계 진행 결과 _N월 X건 총 Y건 ]` 의 Y + 신규 건수. 시트 전체 행 수와 다르면
review.md 에 경고만 남기고 진행한다(`selection.total_count_source: "sheet_rows"` 로 바꾸면 행 수 사용).

## 시트 구조가 바뀌면

앵커를 못 찾으면 스크립트가 즉시 실패하고 기대 라벨을 출력한다. 컬럼이 늘거나 이름이 바뀌면
`sheet_to_proposals.py` 의 `COLUMN_MAP` 과 `config.sheet.anchor_labels` 를 고친다. 추측으로 인덱스를 밀지 말 것.
